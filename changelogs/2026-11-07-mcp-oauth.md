# MCP OAuth Sign-In

**Date**: November 7, 2026
**Version**: 1.10.0
**Issue**: [#116](https://github.com/MarimerLLC/calendar-mcp/issues/116) — part 1 (part 2 adds key expiry and an MCP Access page)

---

## Summary

MCP clients can now connect to the HTTP server with OAuth (the MCP authorization spec) instead of
an API key. The server is its own authorization server: you add its URL to Claude Code, claude.ai /
Claude Desktop (custom connector) or VS Code, sign in to the admin console with Google or
Microsoft, approve the client on a consent page, and it's connected.

This picks up phase 6 of [#81](https://github.com/MarimerLLC/calendar-mcp/issues/81).

## Not a breaking change

- API keys (`cmcp_...`, `X-Api-Key`, `CALENDAR_MCP_MCP_KEY`) work exactly as before.
- OAuth is only offered while an admin sign-in provider (Google or Microsoft) is configured. On a
  server without one, nothing changes: the new endpoints answer `404` and the `401` challenge is
  the same as before.
- Set `CalendarMcp:Mcp:EnableOAuth` to `false` to turn it off entirely.

## What changed

- **Authorization server** (OpenIddict): `/connect/authorize`, `/connect/token`, `/connect/revoke`,
  `/connect/register` (dynamic client registration), discovery at
  `/.well-known/oauth-authorization-server` and `/.well-known/openid-configuration`, and protected
  resource metadata at `/.well-known/oauth-protected-resource`. Client ID metadata documents are
  supported too. Authorization code with PKCE (S256) only; public clients only.
- **Consent page** at `/connect/consent`, shown on every authorization.
- **MCP endpoint** accepts an API key or an OAuth access token issued for it. The `401` challenge
  adds `resource_metadata` when OAuth is offered.
- **Revalidation**: an OAuth token stops working as soon as its owner is removed from the
  admin allow-list, or OAuth is turned off.
- **Admin sign-in** now returns to where it was started (a local `returnUrl`), including through
  the first-run claim flow, so the OAuth round trip comes back to the client's request.
- **Rate limits**: dynamic registration 10/hour per address; other OAuth endpoints 60/minute.
- **New files in the data directory**: `identity.db` (SQLite: registered clients, approvals,
  refresh tokens) and `oauth-keys/` (generated token keys, encrypted with the DataProtection
  keyring). Keep the data directory on a local disk or block volume, not a network file share.
- **New settings**: `CalendarMcp:Mcp:EnableOAuth`, `CalendarMcp:Mcp:SigningCertificate`,
  `CalendarMcp:Mcp:EncryptionCertificate`.
